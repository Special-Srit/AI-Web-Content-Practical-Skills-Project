## 0. 페르소나 유형 라벨링 — 먼저 밝힐 것

```
유형: 프로토 페르소나 (proto-persona)
근거: 경쟁사 분석 + 추론 — 인터뷰·설문 없음
      상세 조사 표 18행 (세그먼트 A 직접경쟁 8 · B 인접 관리앱 7 · C 테스트 플랫폼 3)
      + 학술 논문 3편 (Litchfield 2017 · Bennett 2017 · Ha & Ha 2017)
      + 검증 실패·존재 불명 13건 (404·삭제·수치 과장 포함)
한계: 실제 사용자 데이터가 아니므로 일반화 불가
용도: 설계 초점 도구 — 데이터로 주장하지 않음
검증 계획: 실제 집사 5명 롤링 인터뷰 (새 인사이트가 안 나올 때까지, 5~30명)
      ① 문항을 소리내어 답하게 하고 "모르겠음" 응답 비율 측정
      ② 금지 목록이 추천 처방보다 유용한지 직접 물어보기
      ③ 2주 후 재검사 의향 여부
      ④ 다묘 가구에 성향 비교 화면이 실제로 필요한지
가장 약한 가정: "집사가 자기 고양이의 행동을 문항으로 답할 수 있을 만큼 관찰하고 있다"
      틀리면 → 입력 자체가 성립하지 않아 검사 구조 전체가 무너짐
      특히 주 페르소나(초보 집사)와 부재 시간이 긴 맞벌이에게 위험
      대응 설계: "모르겠음" 선택지 + 관찰형 문항 프레이밍 (아래 기능 후보 1·2번)
```

**용어 근거** — 리서치 없는 페르소나의 정식 명칭 = proto-persona (Gothelf) / ad-hoc·assumption persona (Adlin 2007). NN/g가 인정하는 3유형 중 하나, 정당 조건은 *"if the team considers them to be hypotheses that can be validated with research."* Norman: *"they only need to be realistic, not real, not necessarily even accurate."*

## 1. 방법론상 긴장 — 뭉개지 않고 선택한 지점 3개

- **① 필수 필드는 인구통계 위주, 그러나 차이는 행동에서 나와야 함**
  - Goodwin: *"The important distinctions among personas are behavioral, not demographic."*
  - 선택 — **필수 필드 전부 유지**(수업 요구사항, 협상 불가) + 인구통계는 **맥락**으로만 취급
  - 세 페르소나의 실제 분기는 §2의 **행동 축 표**에 있음, 프로필이 아님
  - 자체 검사 — 세 명의 인구통계를 서로 맞바꿔도 필요 기능이 안 바뀌면 실패. §2 표로 통과 확인
- **② 이름·사진 필요성은 출처 간 이견 있음 — 평균 내지 않고 선택**
  - 필요 측: Cooper(사진이 현실감 부여) · NN/g Dykes(기억 보조가 페르소나의 주 임무)
  - 불필요·유해 측: Norman(*"completely superfluous"*) · NN/g Laubheimer 2022(한 얼굴은 *"inherently reductive"*, 안 담긴 사람을 암묵적 배제) → 대안은 이름·얼굴 없는 **archetype**
  - 선택 — **사진 채택**, 이유는 수업 필수 요구사항. 다만 방법론적으로 결론난 문제 아님 → 발표에서 한 줄 고지
- **③ AS-IS / TO-BE 4칸 프레임의 출처는 확인 실패**
  - 1차 출처 추적 실패 — 교재·에이전시 방법론 문서·논문 어디에도 없음. 국내 SI·ISP 산출물의 일반 분석 프레임으로만 확인
  - 사용은 함(강사가 가르치고 채점 대상) — 다만 **유래를 주장하지 않음**
  - 구조적 결함 — 4칸에 **행동 패턴·사용 맥락 자리가 없음**. 그것만 채우면 Cooper가 말한 "user profile = user stereotype" 함정
  - 대응 — 행동 패턴·사용 맥락을 §2 축 표와 프로필 항목으로 **따로** 들고 감

## 2. 행동 축 — 페르소나의 합격 여부가 결정되는 곳

- 축 없이 결과만 있으면 고정관념 의심을 받음 → 축을 문서에 명시
- **각 축은 서로 다른 기능을 가리켜야 함** — 셋이 같은 기능을 원하면 IA에 근거가 안 생김

| 행동 축 | A. 오세진 (초보) | B. 문서연 (맞벌이) | C. 임현석 (다묘) | 이 축이 가리키는 기능 |
| --- | --- | --- | --- | --- |
| 해석 공백의 성격 | 판단 기준 자체가 없음 — 모든 행동이 미지 | 기준은 있으나 확인할 시간 없음 — 결론만 원함 | 개체별 지식은 충분 — **비교 축**이 없음 | 유형 서사 / 처방 요약 / 다묘 비교 |
| 고양이와 떨어져 있는 시간 구조 | 짧음 — 퇴근 후 계속 붙어 있음 (과잉 접촉) | 김 — 평일 10시간 이상 부재, 저녁에 몰아치기 | 중간 — 가게 왕복으로 분산, 대신 3마리로 쪼개짐 | 접촉 강도 조절 / 부재 중 자율 놀잇감 / 개체별 시간 배분 |
| 놀이 실행 방식 | 반응이 무서워 시도 자체를 줄임 | 밤 20~30분 집중, 시각이 고양이 활동기와 어긋남 | 셋이 뒤엉켜 한 마리에게만 못 줌 | 금지 목록 / 놀이 시각 권고 / 자원 분리 권고 |
| 구매 계기 | 커뮤니티 추천을 전부 시도 → 실패 누적 | 실패 비용이 아까워 **1종만 정확히** 사고 싶음 | 이미 다수 보유 — 신규 구매가 아니라 **배분** 문제 | 유형별 장난감 3블록 / 유형별 우선순위 1종 표기 |
| 공유·저장 동기 | 커뮤니티에 **질문 첨부용**으로 결과 공유 | **배우자와 양육 합의용** 링크 공유 | 공유 동기 낮음 — 내부 비교표를 저장·재열람 | 결과 카드 이미지 / 유형별 정적 결과 URL / localStorage 저장 |
| 재검사 행동 | 적응기라 2~4주 내 재검사 의향 높음 | 1회성 — 다시 안 열 가능성 높음 | 새 개체 합사·서열 변동 시점마다 재검사 | 재검사 안내 / 검사일 기록 |

**통과 판정** — 세 명은 최소 한 개 이상의 유의미한 행동에서 서로 다름(Cooper 요건 충족). 인구통계를 서로 맞바꿔도 축 위치는 바뀌지 않음 → 인구통계 연극 아님.

**디테일 규칙** — 리서치 깊이(=0건 인터뷰)를 넘지 않도록 **범위·어림수만** 사용. 정확한 주소·정확한 월 지출·정확한 나이는 쓰지 않음 (Cooper: 35.421 m로 적으면 0.001 m 정밀도를 주장하는 것). 나이는 행동이 갈리는 경우에만 정확히 표기 — 세 명 모두 해당 없음 → 연령대만 표기.

## 3. 페르소나 A — 오세진 (초보 집사) · **주 페르소나**

### 기본 프로필

- **이름·나이·성별** — 오세진 / 20대 후반 / 남
- **직업** — 물류회사 사무직, 정시 출퇴근
- **가족 구성** — 1인 가구, 고양이와 단둘
- **거주지 + 거주형태** — 수도권 도심 원룸, 월세, 좁은 단일 공간 (캣타워 놓을 자리 사실상 없음)
- **인물 이미지 스펙** (파일은 Srit이 직접 조달 — 여기서는 요구 조건만 명시)
  - 담아야 할 것 — 좁은 원룸 배경 / 20대 후반 남성이 **바닥에 앉아 거리를 두고** 고양이를 바라보는 구도 / 손을 내밀지 않은 상태 = 조심스러움이 읽히게
  - 담지 말 것 — 고양이를 껴안은 사진(이 페르소나의 행동과 반대), 넓은 거실, 연예인
  - 조달 — 무료 라이선스 스톡(상업 이용 가능 라이선스 확인 필수) 또는 AI 생성 이미지. 사용한 쪽을 캡션에 표기
  - 페르소나당 1장

### 반려묘 정보

- **품종** — 코리안 숏헤어 (보호소 입양)
- **나이** — 1살 미만
- **함께 지낸 기간** — 4개월 남짓

### 라이프스타일

- **하루 루틴** — 오전 출근 → 야근 거의 없음 → **퇴근 후 곧장 귀가**, 저녁 대부분을 고양이 관찰에 씀 → 커뮤니티·유튜브로 행동 검색
- **고양이와 함께 보내는 시간** — 하루 4~5시간, 퇴근 후 저녁 ~ 취침 전
- **월 지출** — 월 10~20만원대 (사료·모래 기본 + 장난감 소액 반복 구매)
- **고양이 쪽 루틴** — 낮 9~10시간 혼자, 새벽에 우다다, 사람이 자려 누우면 발끝을 물음

### 앱이 필요한 이유

- 4개월치 관찰만 있음 → **행동 하나하나가 좋은 신호인지 나쁜 신호인지 판단 기준이 없음**
- 검색하면 "고양이란 원래 그렇다" 일반론만 나옴 — 우리 집 이 아이 얘기가 아님
- 관리 앱은 **기록만 하고 해석은 안 함** (02-market-research 세그먼트 B — 조사 7개 전부 성향 기능 0건)
- 국내 접근성 높은 테스트는 대상이 **집사 본인** (푸망·BLTI·포캣멍센터) → 우리 고양이를 재주는 곳이 없음

### 필요 기능 / 무시할 기능

- **쓸 것** — 짧은 관찰형 검사 · **금지 목록("하지 마세요")** · 유형 서사 · 근거 표기 · 재검사
- **무시할 것** — 다묘 비교(해당 없음) · 장난감 다수 추천(이미 실패 누적, 1종 우선순위만 원함)

### 페인포인트 (구체 사건)

- 입양 3주째, 무릎에 올라와 있던 아이에게 손을 뻗었더니 **하악질** — 이유를 모르는 채로 그 뒤 만지기를 겁냄
- 커뮤니티 추천 장난감을 사서 흔들었더니 도망 → "내가 뭘 잘못했는지" 확인할 방법이 없음

### AS-IS / TO-BE

| 구분 | 내용 |
| --- | --- |
| AS-IS · 동기 | "이 아이가 왜 이러는지 하나도 모르겠어" — 판단 기준 부재 상태 |
| AS-IS · 니즈 | "어떤 성향인지 알고 싶어" / **"하면 안 되는 걸 먼저 알고 싶어"** |
| TO-BE · 얻는 지식 | 결과가 신경성 높은 계열로 나옴 → 하악질이 거부 신호이며 **갑작스러운 안기·정면에서 손 뻗기가 금지 항목**이라는 정보를 얻음 |
| TO-BE · 행동 변화 | 손등을 먼저 내밀고 기다리는 방식으로 바꿈 + 원룸 구석에 은신처 1곳 마련 (Feline Five 논문의 보호자 권고: 신경성 높음 → 은신처 추가 제공) |

## 4. 페르소나 B — 문서연 (맞벌이 집사) · **보조 페르소나 (supplemental)**

### 기본 프로필

- **이름·나이·성별** — 문서연 / 30대 중반 / 여
- **직업** — 중소기업 디자인팀, 배우자도 정규 출근직 (맞벌이)
- **가족 구성** — 부부 2인, 자녀 없음, 고양이 1마리
- **거주지 + 거주형태** — 경기권 신도시 아파트, 전세, 방 2~3개 규모 (캣타워 설치 여유 있음)
- **인물 이미지 스펙**
  - 담아야 할 것 — 아파트 거실 배경 / 30대 중반 여성이 **퇴근 복장 그대로 소파에 앉아** 장난감을 든 구도 / 고양이는 조금 떨어져 대기 = 짧고 몰아치는 놀이 시간이 읽히게
  - 담지 말 것 — 한가한 주말 분위기, 여러 마리, 연예인
  - 조달 — 무료 라이선스 스톡 또는 AI 생성, 사용한 쪽 표기 / 1장

### 반려묘 정보

- **품종** — 러시안 블루
- **나이** — 3살 전후
- **함께 지낸 기간** — 약 3년 (아기 때부터)

### 라이프스타일

- **하루 루틴** — 부부 둘 다 출근, 재택 없음 → 퇴근 후 저녁 준비·각자 시간 → **밤에 20~30분 몰아서 놀아줌** → 검색은 거의 안 함, 결론만 원함
- **고양이와 함께 보내는 시간** — 하루 2시간 이내, 대부분 밤 시간대
- **월 지출** — 월 20~30만원대 (사료·모래·병원 적립 + 장난감 간헐 구매)
- **고양이 쪽 루틴** — 평일 10시간 이상 혼자, 사람이 돌아오면 격하게 놀이 요구, 새벽 3~4시에 활동 개시

### 앱이 필요한 이유

- 3년을 같이 살아 성향은 대략 아는데 **부재 시간에 맞는 실행안**이 없음
- 시간이 없어서 **실패 비용을 크게 체감** — 사놓고 안 쓰는 장난감이 쌓임
- PurrJung은 한국어가 되지만 **장난감·놀이 처방이 없음**, IDRLabs는 한국어 미지원 + 권고 제공을 명시적으로 거부 (02-market-research 세그먼트 A)
- 즉 "우리 고양이 유형 → 오늘 뭘 할지"를 한국어로 이어주는 곳이 없음

### 필요 기능 / 무시할 기능

- **쓸 것** — 유형별 **추천 놀이·추천 장난감·상호작용 방식 3블록** · 자율 놀잇감(부재 중) 항목 · 배우자에게 보낼 결과 링크·카드 · 3분 이내 소요
- **무시할 것** — 재검사(1회성) · 다묘 비교 · 논문 근거 상세(있으면 신뢰하지만 안 읽음)

### 페인포인트 (구체 사건)

- 커뮤니티 추천 1위 낚싯대 장난감을 샀는데 3일 만에 쳐다보지도 않음 — 서랍에 미개봉·방치 장난감 5~6개 적립
- 밤 11시에 놀아주려 하면 이미 자고, 새벽 4시에 깨어나 부부가 번갈아 깨는 일이 반복 → 배우자와 언쟁

### AS-IS / TO-BE

| 구분 | 내용 |
| --- | --- |
| AS-IS · 동기 | "낮에 혼자 있는 시간을 어떻게 채워줘야 할지 모르겠어" — 부재 시간 대응 부재 |
| AS-IS · 니즈 | "우리 아이한테 맞는 것 **딱 하나만** 알고 싶어" / "언제 놀아주는 게 맞는지 알고 싶어" |
| TO-BE · 얻는 지식 | 결과가 외향·충동 높은 계열로 나옴 → **하루 15분 사냥 놀이 2회 + 부재 중 자율 놀잇감**이 필요하다는 정보를 얻음 (논문 권고: 외향성 높음 → 환경 풍부화 / 충동성 높음 → 환경 스트레스 요인 점검) |
| TO-BE · 행동 변화 | 낚싯대류 재구매를 그만두고 유형 우선순위 1종만 구매, 놀이 시각을 밤 11시 → **귀가 직후 + 취침 직전 2회**로 조정, 결과 링크를 배우자에게 보내 역할 분담 합의 |

## 6. 주 페르소나 지정 — 소거법

**원칙** — Cooper: *"There can be only one primary persona per interface for a product."* 판정 기준은 인기·매출·대표성이 아님

> *"A primary persona is not satisfied by a design targeted at any other persona in the set. However, if the primary persona is the target, all other personas are at least minimally satisfied."*

### 소거 과정

- **B(맞벌이)를 타깃으로 설계하면** → 문항 최소 + 장난감 추천 한 장으로 수렴
  - A는 불만족 — 판단 기준·금지 목록·"모르겠음" 처리가 없어 **입력조차 못 함**
  - C도 불만족 — 비교 축 없음
  - → B는 primary 아님
- **C(다묘)를 타깃으로 설계하면** → 여러 마리 등록·비교가 첫 화면
  - A는 불만족 — 비교 화면은 **한 마리를 읽을 줄 안다는 전제** 위에 서 있음. 초보에게는 진입 자체가 과부하
  - B도 불만족 — 등록 단계가 늘어 3분 안에 안 끝남
  - → C는 primary 아님
- **A(초보)를 타깃으로 설계하면** → 짧은 관찰형 문항 + "모르겠음" 허용 + 유형 서사 + 처방 3블록 + 금지 목록 + 근거 표기
  - B는 **최소 만족** — 처방 3블록과 짧은 소요 시간이 B의 요구와 그대로 일치, 추가 요구 없음
  - C는 **최소 만족 + 추가 니즈 1개** — 검사·처방·금지 목록은 그대로 쓰고, 비교 화면만 더 필요
  - → **A가 주 페르소나**

### Goodwin의 반직관 규칙과도 일치

- Goodwin: 가장 **만족시키기 어려운** 사람을 primary로 (기내 엔터테인먼트 사례의 *"the retired bricklayer"*)
- 이 세트에서 가장 어려운 사람 = **A** — 관찰 데이터가 가장 적고, 사전 지식이 없고, "모르겠음"을 가장 많이 누를 사람
- A 기준으로 설계하면 B·C는 약간의 추가로 만족, 역방향은 불가 → 소거 결과와 Goodwin 규칙이 같은 답을 냄

### 등급과 설계상 의미

| 페르소나 | 등급 | 설계에 미치는 영향 |
| --- | --- | --- |
| A 오세진 (초보) | **primary** | 모든 기본 흐름의 기준 — 문항 난도·"모르겠음" 허용·금지 목록 배치·유형 서사 분량을 A로 결정 |
| C 임현석 (다묘) | **secondary** | 기본 흐름 그대로 + 추가 니즈 1개(다묘 비교). **primary의 동선을 방해하지 않는 위치**에만 넣음 — 결과 화면 하단 또는 별도 진입점, 첫 화면에 노출 금지 |
| B 문서연 (맞벌이) | **supplemental** | primary 설계로 **이미 완전 만족** — 설계를 바꾸지 않음. B만을 위한 기능 추가 금지 |

- 정직하게 남길 관찰 — Cooper의 지적: **이해관계자 요구로 추가된 페르소나는 대개 supplemental로 정리됨**. B가 정확히 그 경우 — 강사 예제의 3케이스를 따라 넣었고, 소거해보니 독자적 설계 요구가 없음. 케이스로서는 유효하나 설계 결정권은 없음
- primary가 2명 이상 나오면 제품 범위가 너무 넓다는 신호 — 이번엔 1명으로 수렴 → 범위 경고 없음

## 7. 공통 니즈 → 도출된 기능 후보 (IA 단계가 소비할 목록)

### 7-1. 셋 모두에게 공통인 니즈

- **일반론이 아닌 "우리 집 이 고양이 한 마리"의 개별 판독** — 셋 다 검색으로는 해결 못 함

- **결과를 남기고 다시 열어보기** — A는 재검사용, B는 배우자 공유용, C는 비교용

### 7-2. 도출된 기능 후보 — 전부 백엔드 없이 구현 가능

1. **16문항 이내 · 1문항 1화면 · 관찰형 프레이밍** — "최근 일주일 동안" 기준으로 질문 (기억 의존 축소)
2. **"모르겠음 / 관찰 못 함" 선택지** — 가장 약한 가정에 대한 직접 대응, 가중치 계산에서 제외 처리
3. **결과 = 처방 3블록 고정** — 추천 놀이 / 추천 장난감 / 상호작용 방식, 정적 JSON으로 전량 사전 작성
4. **금지 목록 블록 "이 아이한테 하지 마세요"** — 유형별 역권고 2~3개, 결과 화면 상단권 배치 (공통 니즈 3번의 직접 구현, 전 경쟁사 미제공)
5. **장난감 우선순위 1종 명시** — 목록 나열이 아니라 "먼저 이것 하나" (A의 실패 누적 · B의 실패 비용 대응)
6. **근거 표기 블록** — Feline Five(PLOS ONE 2017) 참고 + **탐색적 연구라 검증된 측정도구가 아님**을 한 줄로 명시 + 4축 16유형은 재미를 위한 단순화임을 분리 표기
7. **결과 카드 이미지 생성** — Canvas 렌더 → `canvas.toBlob()` + Web Share API로 저장·공유 (순수 클라이언트)
8. **유형별 정적 결과 페이지 + 유형별 `og:image`** — 답변은 쿼리스트링 전달, 서버 저장 불필요. 1등 플랫폼(푸망) 패턴을 정적으로 재현한 것 — 신규 발상 아님

10. **자원 분리 권고 블록** — 유형 조합(우월성 높음 × 신경성 높음 등)에 대응, 논문의 보호자 권고를 근거로 인용
11. **검사일 기록 + 재검사 안내** — localStorage에 날짜 저장, 일정 기간 경과 시 재검사 유도 (A·C의 재검사 행동 대응)
12. **회원가입 없음 · 모바일 우선** — DBTI·PurrJung 공통 성공 조건

## 8. 페르소나의 한계 — 미리 밝히고 가는 부분

가장 강한 학술 비판은 Chapman & Milham (HFES 2006)의 **반증 불가능성** 지적이다. 논문의 표현은 *"Because personas are admittedly fictional ... no data can disprove a fictional construction. Therefore, they are outside the scientific method."* 페르소나는 허구이므로 어떤 데이터로도 반박할 수 없고, 따라서 과학적 방법의 범위 밖이라는 것이다. 같은 논문은 **차원의 저주**도 지적한다 — 속성이 21개면 기저율 0.5 가정하에 실제 해당 인구가 0.000048%로 줄어들어, 페르소나 한 명이 몇 명을 대표하는지 알 수 없게 된다. Rönkkö(2005)의 관찰도 함께 인용된다: 페르소나가 *"served primarily to justify decisions that were actually made on other grounds"* — 다른 이유로 이미 내린 결정을 정당화하는 데 쓰였다는 것.

다만 그 논문은 **탈출구를 직접 남겨두었다.** *"design inspiration with no claim to validity"* 용도는 논문 범위에서 명시적으로 제외되며, 결론부의 요구는 *"the method should not claim to be a source of data"* 하나다. 즉 이 비판은 "쓰지 말라"가 아니라 **데이터라고 주장하지 말라**는 요구다.

**본 문서의 입장** — 위 세 페르소나는 인터뷰 0건·설문 0건에서 나온 프로토 페르소나이며, **설계 초점 도구**로만 사용한다. 사용자 데이터가 아니고, 시장 규모나 사용자 비율의 근거로도 쓰지 않는다(시장에 관한 서술은 전부 `02-market-research.md`로 추적 가능한 실측 조사에서만 온다). 검증된 효용은 "사용자를 정확히 아는 것"이 아니라 **무엇을 안 만들지 결정하는 것**이며(Miaskiewicz & Kozar 2011의 전문가 패널 순위, Norman의 empathetic focus), §6의 등급 지정과 §7-3의 범위 외 목록이 정확히 그 용도로 쓰인 결과다. 데이터라고 주장하지 않는 이 자리에서는 비판의 사정권 밖에 있다.

**남는 위험 2개, 숨기지 않고 기록**

- **에코 체임버** — NN/g의 경고 그대로, 프로토 페르소나는 *"an echo chamber for the team's incorrect assumptions"*가 될 수 있음. 특히 팀 2인·양쪽 다 집사 경험이 편중될 경우 자기참조적 설계로 흐를 수 있음 → §0의 검증 계획(5명 롤링)이 유일한 해소 경로
- **고정관념 열화** — 리서치가 없으면 고정관념 위험이 구조적으로 올라간다는 것이 Cooper 본인의 진술. 이 프로젝트의 명백한 함정은 "고양이 좋아하는 사람" 스테레오타입 → 대응으로 §2의 행동 축을 먼저 정하고 프로필을 나중에 채웠으며, 세 명 중 두 명을 남성으로 두어 성별 편중도 피함

## 9. 고객 여정 지도 (저니맵) — 공감 지도 합쳐서 진행

강사 배포 자료(`프레젠테이션1.pptx` 19~20장) 양식을 그대로 따름.

- **7단계 고정** — 인지 · 유입 · 온보딩 · 테스트 진행 · 결과 확인 · 케어 가이드 확인 · 재방문
- 각 단계마다 **생각·행동 / 감정 상태 / Pain Point / 기회 요소** 4행
- 감정 곡선을 의도적으로 설계 — **결과 확인에서 하락, 케어 가이드 확인에서 회복**
  - 그 회복 지점이 **Aha Moment**
- 일반론 대신 페르소나 **본인의 말**을 인용문으로 넣음

**중요 — 세 명의 Aha Moment는 같은 단계, 다른 내용**

- 단계는 같지만 무엇이 회복시키는지가 다름 → 셋이 실제로 다른 사람이라는 증거
- A는 **금지 목록**, B는 **우선순위 1종**, C는 **유형 조합별 자원 분리**

### 9-1. A · 오세진 (초보 집사) · 주 페르소나

**기대** — "우리 고양이 행동이 정상인지, 왜 그러는지 쉽게 알고 싶어"

| 단계 | 생각·행동 | 감정 | Pain Point | 기회 요소 |
| --- | --- | --- | --- | --- |
| 인지 | 하악질 검색 중 커뮤니티 글에서 결과 카드를 봄 — "이거 우리 애도 해볼 수 있나?" | 기대 (보통) | 검색 결과가 전부 일반론 — "고양이는 원래 그래요" | 결과 카드가 곧 유입 경로 → 유형별 `og:image` 분리 |
| 유입 | 링크 진입, 가입 요구하면 바로 나갈 생각 | 경계 → 안심 | 가입·권한 요구에 민감 | **회원가입 없음**을 첫 화면 상단에 명시 |
| 온보딩 | 문항 수와 소요 시간 확인 — "내가 우리 애 걸 답할 수 있나?" | 불안 (하락 시작) | **관찰하지 않은 항목이 나올까 두려움** | "최근 일주일 관찰" 프레이밍 + **"모르겠음" 있음을 미리 고지** |
| 테스트 진행 | 4지 선다 탭, 애매하면 모르겠음 선택 | 몰입, 간헐적 막힘 | 처음 키워서 비교 기준 자체가 없음 | 진행률 표시 · 이전 이동 시 답변 유지 · 모르겠음 가중치 제외 |
| 결과 확인 | 유형명과 설명을 읽음 — **"그래서 내가 뭘 해야 하지?"** | **아쉬움 (최저점)** | 유형 설명만으로는 행동이 안 바뀜 — 경쟁사 다수가 여기서 끝남 | 결과 화면 **상단**에 처방 진입점 배치 |
| 케어 가이드 확인 | 추천 놀이·장난감을 보고, **금지 목록에서 "갑자기 안기" 를 발견** | **납득·안도 (최고점)** | 권장만 있으면 이미 하던 것과 구분이 안 됨 | **금지 목록이 이 페르소나의 Aha** — 하악질 원인이 자기 행동이었음을 알게 됨 |
| 재방문 | 적응기 지난 2~4주 후 재검사, 이전 결과와 비교 | 기대 | 이전 결과가 없으면 변화를 확인 못 함 | 검사일 기록 + localStorage 저장 + 재검사 안내 |

### 9-2. C · 임현석 (다묘가정 집사) · 2차 페르소나

**기대** — "셋 중 누가 문제인지 판정하고 싶어"

| 단계 | 생각·행동 | 감정 | Pain Point | 기회 요소 |
| --- | --- | --- | --- | --- |
| 인지 | 다묘 커뮤니티에서 합사 갈등 글을 읽다 발견 | 반신반의 | 다묘 상황을 다루는 자료가 거의 없음 | 다묘 키워드로 진입하는 경로 확보 |
| 유입 | "세 마리를 다 해야 하나" 부담을 먼저 느낌 | 망설임 | 반복 입력 부담이 진입 장벽 | 한 마리만 먼저 해보고 추가할 수 있게 안내 |
| 온보딩 | 개체별로 따로 답해야 함을 확인 | 부담 | 공통 정보를 세 번 다시 입력 | 가구 공통 정보는 **재사용**, 개체 정보만 추가 입력 |
| 테스트 진행 | 3회 반복 응답 | 피로 누적 | 3회째에 집중력 저하 | 마리별 진행 상태 저장 → 중단·재개 가능 |
| 결과 확인 | 개체별 유형은 나오는데 **나란히 볼 수가 없음** | **답답함 (최저점)** | 개별 결과만으로는 갈등 원인 판정 불가 | 결과 화면에서 **비교 화면 진입점** 제공 |
| 케어 가이드 확인 | 유형 조합을 보고 **자원 분리 권고**를 확인 | **납득 (최고점)** | 일반적인 다묘 조언은 "천천히 합사하세요" 수준 | **유형 조합별 자원 분리 권고가 이 페르소나의 Aha** |
| 재방문 | 새 개체 합사·서열 변동 시점마다 재검사 | 필요 기반 | 변동 시점을 스스로 기억해야 함 | 검사일 기록 + 개체 추가 시 비교 갱신 |

### 9-3. B · 문서연 (맞벌이 집사) · 보조 페르소나

**기대** — "짧은 시간이라도 제대로 해주고 싶어"

| 단계 | 생각·행동 | 감정 | Pain Point | 기회 요소 |
| --- | --- | --- | --- | --- |
| 인지 | 배우자가 보낸 링크 또는 SNS 노출 | 가벼운 관심 | 관심은 있으나 탐색할 시간이 없음 | 링크 미리보기에서 소요 시간이 보이게 |
| 유입 | 밤에 짧게 확인, 오래 걸리면 즉시 이탈 | 조급함 | 로딩·가입 단계가 곧 이탈 지점 | 즉시 시작 · 회원가입 없음 |
| 온보딩 | 소요 시간 확인 — "3분이면 지금 할 수 있네" | 안심 | 시간이 불명확하면 시작 자체를 미룸 | **소요 시간을 시작 버튼 옆에 명시** |
| 테스트 진행 | 한 번에 몰아서 응답 | 무난 | 중간에 끊기면 다시 안 옴 | 이탈 없이 끝낼 수 있는 짧은 길이 |
| 결과 확인 | 유형 확인 — **"그래서 뭘 사면 되지?"** | **미흡 (최저점)** | 유형 서사는 B에게 효용이 낮음 | 결과 상단에 **구매 판단으로 바로 가는 경로** |
| 케어 가이드 확인 | 추천 장난감 중 **우선순위 1종**을 확인 | **결정 완료 (최고점)** | 3~5개를 추천하면 다시 고민이 늘어남 | **"이것부터" 1종 명시가 이 페르소나의 Aha** |
| 재방문 | 재방문 동기 낮음 — 1회성으로 끝날 가능성 | 무관심 | **재방문 설계로는 잡히지 않는 페르소나** | 배우자 공유 링크로 **확산**을 대신 노림 |

- B의 재방문 단계는 **의도적으로 비어 있음** — supplemental 등급과 일관됨
- B 전용 재방문 기능을 만들지 않는 근거로 이 칸을 그대로 인용할 수 있음

## 10. 여정 지도에서 추가로 도출된 기능 후보

§7의 목록에 없던 것만. 전부 백엔드 없이 구현 가능.

| 기능 | 근거 (어느 단계의 Pain에서 나왔는가) |
| --- | --- |
| 첫 화면 상단에 **회원가입 없음 · 소요 시간** 명시 | A 유입(가입 민감) · B 온보딩(시간 불명확) |
| 검사 전 안내 — "최근 일주일 관찰 기준", "모르겠음 있음" | A 온보딩 — 가장 약한 가정을 정면으로 완화 |
| 결과 화면 **상단**에 처방 진입점 | A·B·C 결과 확인 단계의 공통 최저점 |
| 결과 화면에서 **비교 화면 진입점** | C 결과 확인 — 개별 결과만으로는 판정 불가 |
| 가구 공통 정보 재사용 (개체만 추가 입력) | C 온보딩 — 3회 반복 입력 부담 |
| 마리별 진행 상태 저장 → 중단·재개 | C 테스트 진행 — 3회째 집중력 저하 |
| 검사일 기록 + 재검사 시 이전 결과 비교 | A 재방문 · C 재방문 |
| 공유 링크에 유형 표시 | B 재방문 대체 — 배우자 합의·확산 |

**범위 외로 남는 것** — 재방문 알림(푸시·메일)은 서버 필요. localStorage 기반 "지난 검사일" 안내로만 대체.

## 11. 유저 시나리오

배포 자료에는 이 단계 양식이 없음 (메인 덱이 저니맵 → IA로 바로 넘어감).
1-2에서 제시된 파이프라인에는 존재하는 단계이므로, 양식은 Cooper의 시나리오 3종을 사용.

| 종류 | 무엇을 쓰는가 | 왜 필요한가 |
| --- | --- | --- |
| **맥락 시나리오** | UI 없이 하루 흐름 속 어디서 왜 열게 되는가 | 진입 동기가 실제 생활에 붙어 있는지 검사 |
| **주 경로 시나리오** | 핵심 과업을 처음부터 끝까지 | 화면과 순서를 여기서 뽑아 IA로 넘김 |
| **검증 시나리오** | 예외·실패 상황 | 여기서 나온 목록이 곧 **반드시 처리해야 할 예외** |

- 저니맵은 **감정**을 보고, 시나리오는 **동작**을 봄 — 중복이 아님
- 강사 지시(1-2)의 핵심 요구는 **"무엇을 힘들어할지 예측"** → 각 시나리오에 `예상 난점` 필수

### 11-1. A · 오세진 — 맥락 시나리오 (UI 없음)

- 평일 21시, 퇴근 후 원룸. 저녁 먹고 바닥에 앉아 고양이를 봄
- 손을 뻗었더니 또 몸을 낮춤 — 낮에 하악질했던 게 계속 걸림
- 폰으로 "고양이 하악질 이유" 검색 → 커뮤니티 글 스크롤
- 답이 전부 일반론이라 닫음. 같은 글 아래 누군가 올린 **결과 카드 이미지**를 봄
- 예상 난점 — 이 시점의 목적은 "정보 수집"이 아니라 **"내가 뭘 잘못했는지 확인"**
  - → 서비스 소개가 "성격을 알아보세요"면 동기와 어긋남. **"왜 그러는지"** 로 말해야 함

### 11-2. A · 오세진 — 주 경로 시나리오

1. 결과 카드 링크로 진입 → 첫 화면에서 **회원가입 없음 · 3분**을 확인하고 안심
2. 시작 → 안내에서 **"최근 일주일 관찰 기준", "모르겠음 있음"** 확인
3. 문항 진행. 4번째 문항에서 관찰한 적 없는 상황이 나옴 → **모르겠음** 선택
4. 진행률 60% 지점에서 앞 문항 답을 바꾸려 뒤로 감 → 답변 유지된 채 수정
5. 마지막 문항 후 결과 — 유형명과 설명을 읽고 **"그래서 뭘 해야 하지?"**
6. 결과 상단의 처방 진입점을 눌러 추천 놀이·장난감 확인
7. 아래로 스크롤 → **금지 목록**에서 "갑자기 안기 · 큰 소리" 를 발견하고 원인을 납득
8. 결과 카드를 저장해 커뮤니티 질문에 첨부
- 예상 난점
  - 3번 — 모르겠음을 여러 개 누르면 **결과를 신뢰하지 않게 됨** → 몇 개까지 허용인지 표시 필요
  - 5번 — 유형 설명이 길면 처방까지 도달하지 못하고 이탈
  - 7번 — 금지 목록이 훈계처럼 읽히면 죄책감으로 바뀜 → 문장 톤이 기능만큼 중요

### 11-3. A · 오세진 — 검증 시나리오 (예외)

- **모르겠음을 절반 이상 선택** → 유형 판정이 의미 없어짐
  - 처리: 일정 비율 초과 시 "관찰 후 다시 해보기" 안내 + 잠정 결과 표기
- **중간 이탈 후 며칠 뒤 재진입** → 답변이 남아 있는지 몰라 처음부터 다시 하려 함
  - 처리: 이어하기 / 새로 시작 선택 제시
- **결과 링크를 받은 타인이 진입** → 남의 결과가 자기 결과처럼 보임
  - 처리: 공유된 결과임을 명시 + "내 고양이도 검사하기" 진입점
- **브라우저 데이터 삭제로 localStorage 초기화** → 기록이 사라짐
  - 처리: 서버가 없어 복구 불가임을 저장 시점에 미리 고지 (과대 약속 금지)

### 11-4. C · 임현석 — 주 경로 + 검증

1. 다묘 커뮤니티 글에서 진입, "세 마리 다 해야 하나" 부담을 느낌
2. 안내에서 **한 마리만 먼저 해도 된다**는 문구를 보고 첫째만 진행
3. 결과 확인 후 비교 진입점을 눌렀더니 **비교할 대상이 없음**
4. 둘째·셋째를 이어서 검사 — 가구 공통 정보는 다시 묻지 않음
5. 비교 화면에서 세 유형을 나란히 보고 **자원 분리 권고**를 확인
- 예상 난점
  - 3번 — 한 마리만 한 상태에서 비교 화면이 **빈 화면**이 되면 실패로 읽힘
    - 처리: 비교는 2마리 이상부터 활성화하고, 그 전에는 "한 마리 더 검사" 안내로 대체
  - 4번 — 3회 반복 중 어느 마리를 했는지 혼동 → 마리별 이름·완료 표시 필요
- 검증 — 같은 유형이 두 마리 나옴
  - 처리: "유형이 같아도 갈등은 발생함" 을 전제로 한 권고문 별도 준비

### 11-5. B · 문서연 — 주 경로

1. 배우자가 보낸 링크를 밤에 열어봄. 소요 시간이 안 보이면 바로 닫을 상태
2. 3분 표기를 확인하고 즉시 시작, 중단 없이 한 번에 완료
3. 결과에서 유형 서사는 흘려 읽고 **"뭘 사면 되지"** 로 직행
4. 추천 장난감 중 **우선순위 1종**을 확인하고 그 자리에서 구매 판단
5. 결과 링크를 배우자에게 공유하며 합의
- 예상 난점
  - 3번 — 유형 서사가 처방보다 위에 길게 있으면 **B에게는 방해물**
    - 처리: 처방 블록을 결과 상단에 두고, 서사는 접힌 상태로 아래에
  - 4번 — 추천이 3~5개면 고민이 다시 늘어남 → "이것부터" 1종을 시각적으로 우선 표시

### 11-6. 시나리오에서 새로 나온 요구사항

§7·§10에 없던 것만.

| 요구사항 | 근거 |
| --- | --- |
| 서비스 소개 문구를 **"왜 그러는지"** 기준으로 (성격 소개 아님) | A 맥락 — 진입 동기가 원인 규명 |
| 모르겠음 **허용 비율 표시** + 초과 시 잠정 결과 안내 | A 주 경로 3번 · 검증 |
| 유형 서사는 **접힘**, 처방이 결과 상단 | A 5번 이탈 · B 3번 방해 |

| 이어하기 / 새로 시작 선택 | A 검증 — 중간 이탈 |
