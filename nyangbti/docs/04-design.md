# 04. 설계 — IA · 유저 플로우 · 와이어프레임 (냥BTI)

작성 2026-08-05 · 근거 문서 [03 UX 연구](03-ux-research.md) · 구조 연구 [04-ia-structure-research.md](04-ia-structure-research.md)
범위 — **구조만**(색·타이포·이미지는 Srit이 Figma에서 직접 결정) · 표기 — `03 §7-2 #4` = §7-2의 4번 기능 후보, `[판단]`은 03에 없는 설계 결정

## 0. 확정 전제 (재논의 대상 아님)

- **안 A 채택** — `시작 → 문항 1/16…16/16 → 결과`는 **탭 셸 밖의 선형 플로우**, footer 없음
- 문항 진행 중 표시는 `뒤로 / n/16 / 다음` 뿐
- footer 4탭 = `검사 / 내 기록 / 비교 / 알아보기`, **앱 셸 안에서만** 노출
- 5번째 탭 없음 — 공유·저장·카드 생성·처방 3블록은 **action 또는 result content**이며 destination 아님
- 03 §7-3 범위 외 항목(서버·인증·커뮤니티·기기 간 동기화·사진 분석·카카오 SDK)은 **페이지로 등장하지 않음**

### 0-1. 첫 화면을 셸 밖에 두는 이유 — 03 준수 조건

- 03 §6·§7-2 #9의 문구는 `첫 화면에 노출 금지`이며, "기본 탭이 아님"보다 강한 제약. footer 탭은 **선택되지 않아도 보이는 것 자체가 노출**
- 따라서 첫 화면을 셸 밖에 두는 것이 **`비교`를 탭으로 허용하는 유일한 근거**. 이 경계가 무너지면 4탭 구성 전체의 정당성이 사라짐

### 0-2. 지침에서 의도적으로 벗어나는 지점 (발표에 그대로 사용)

- Apple HIG는 섹션 이동 중에도 탭 바를 계속 보이게 하라고 권고하며, 명시된 예외는 **modal view가 탭 바를 덮는 경우** 하나임 ([Apple HIG — Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars))
- 냥BTI의 문항 화면은 **modal이 아니므로 그 예외에 해당하지 않음** — 예외를 끌어와 정당화하지 않음
- 대신 근거는 Material의 명시적 비적용 규칙 — bottom navigation은 **단일 과업(single task)에 비권장** ([Material Design — Bottom navigation](https://m2.material.io/components/bottom-navigation/))
- 판정 — `시작 → 문항 → 결과`는 single task이므로 **Apple 지침에서 의도적으로 이탈**함을 명시하고, 03의 `첫 화면 노출 금지`를 상위 제약으로 둠

## 2. IA 화면 구조도 (조직도로 다시 그릴 형태)

### 2-1. 레벨 정의 — 조직도의 단(段)

| 레벨 | 의미 | 조직도 표기 |
| --- | --- | --- |
| L0 | 앱 루트 | 최상단 상자 1개 |
| L1 | 영역(zone) — footer 유무가 갈리는 경계 | 2개 상자, 굵은 테두리 |
| L2 | 화면(destination 또는 선형 단계) | 일반 상자 |
| L3 | 상태·오버레이·시트 — 화면 아님 | 점선 상자 |

### 2-2. 구조

```
L0                          냥BTI
                              │
        ┌─────────────────────┴─────────────────────┐
L1   Z1. 검사 선형 플로우 (footer 없음)      Z2. 앱 셸 (footer 4탭)
        │                                            │
L2      ├── S1 시작 화면                     ┌────────┼────────┬────────┐
        │     └╌╌ S1-a 이어하기 분기          T1 검사  T2 내 기록 T3 비교  T4 알아보기
L2      ├── S2 문항 화면 (n/16 · 16단계)       │        │        │        │
        │                                     │        └╌ T2-a  └╌ T3-a  (단일 페이지)
L2      └── S3 결과 화면                       │           0건      0–1마리
              ├╌╌ S3-a 잠정 결과 배너          │
              ├╌╌ S3-b 공유 결과 배너          └──→ S1 로 이동 (셸 이탈)
              ├╌╌ S3-c 저장 시트
              └╌╌ S3-d 공유·카드 시트
```

- **S3는 두 영역에 동시에 속하는 유일한 화면** — 같은 템플릿, 진입 컨텍스트로만 갈림. `C1 검사 직후`·`C3 공유 진입` → **Z1**(footer 없음) / `C2 T2 또는 T3에서 셸 drill-down` → **Z2**(footer 유지, 탭 내부 drill-down)
- 조직도 작성 지시 — S3는 상자 하나로 그리고 `Z1 / Z2` 두 영역에서 화살표를 받게 표기. 상자를 두 개로 복제하면 같은 화면이 둘로 보임

### 2-3. footer 노출 규칙 (구현 분기 1개로 정리)

| 화면 | footer | 근거 |
| --- | --- | --- |
| S1 · S2 | 없음 | 03 첫 화면 노출 금지 + Material single-task |
| S3 (C1 검사 직후 · C3 공유 진입) | 없음 | 선형 플로우의 종점 |
| S3 (C2 T2 또는 T3에서 재열람) | 노출 | 탭 내부 drill-down — 섹션을 벗어나지 않음 |
| T1 · T2 · T3 · T4 | 노출 | 앱 셸 |

- 셸 진입 조건 — **S3의 명시적 진입점을 눌렀을 때만**(저장 / 비교 / 알아보기). 검사를 끝내지 않은 사용자는 셸을 볼 수 없음
- `returnTo` 컨텍스트 — T2·T3·T4에서 셸이 S1로 넘길 때 정확한 원 화면을 기록하며, S1↔S2 및 S1-a 이어하기 분기 동안 유지하고 검사 완료(S3) 또는 취소 시 해제함. S1의 `[×]`는 `returnTo`가 기록된 경우에만 노출하고, 누르면 기록된 T2·T3·T4로 돌아감. T1은 자체 콘텐츠가 없는 검사 탭이므로 `returnTo` 대상이 아님

## 3. 유저 플로우 — 화면 순서

### F1. A 오세진 주 경로 (주 페르소나 · 기본 흐름)

```
(공유 카드 링크 또는 직접 진입)
 → S1 시작 [회원가입 없음·약 3분·16문항 확인]
 → S2 1/16 → … → S2 16/16   (뒤로 = 답변 유지된 채 수정)
 → S3 결과   [처방 3블록 → 금지 목록 → 서사(접힘) 순서, §6 참조]
 → S3-c 저장 시트 [이름 입력 + localStorage 고지]
 → T2 내 기록 (셸 진입, footer 노출)
```

- 분기 — 저장하지 않고 `S3-d 공유·카드 시트`로 이탈 가능(A의 커뮤니티 질문 첨부, §11-2 8)

### F2. B 문서연 주 경로 (추가 설계 없음 — 기본 흐름의 최단 경로)

- `배우자 링크 → S1 [3분 표기 확인] → S2 ×16 → S3 → 처방의 "이것부터 1종"(§7-2 #5) → S3-d 공유 시트 → 링크 복사 → 종료`
- B는 **셸에 들어오지 않고 끝나는 것이 정상 경로** — supplemental 등급과 일관

### F3. C 임현석 주 경로 (다묘)

```
S1 → S2 ×16 → S3(첫째) → S3-c 저장[이름: 첫째]
 → T2 → footer [비교] T3 → T3-a 비교 불가(1마리) → [한 마리 더 검사]
 → S1 → S2 ×16 → S3(둘째) → S3-c 저장[둘째]
 → T2 → footer [비교] T3 (2마리 이상 → 활성) → 자원 분리 권고
    (같은 유형 2마리면 전용 권고문으로 대체, §11-4 검증)
```

### F4. 재검사 (A 재방문 · C 서열 변동)

- `T2 → 개체 항목 탭 → S3 재열람(C2, footer 유지) → T2의 [재검사] → S1(이름 프리필, 셸 이탈) → S2 ×16 → S3 → S3-c 저장 → T2`
- S3 재열람 시 `이전 검사: 유형 · 날짜` 1줄 비교 표시 (§10 재검사 시 이전 결과 비교)
- `[재검사]`는 T2 개체 카드만 소유하며 → S1로 이동함. 검사일로부터 일정 기간 경과 시 T2에서 재검사를 유도함(03 §7-2 #11)
- 보관 정책 [판단] — 개체당 **직전 1회분만** 보관, 재검사 시 최신→이전으로 밀어냄. 추이 그래프는 03 §7-3 범위 외이므로 만들지 않음 → **§10의 확인 항목 2**

### F5. 공유 링크로 진입한 타인

- `쿼리스트링 URL → S3 (C3)` — S3-b 배너로 "다른 집사의 고양이 결과"임을 명시
- `→ [내 고양이도 검사하기] → S1 → 이후 F1과 동일`

### F6. 중단 후 재개

- `S2 도중 이탈 → (재진입) → S1 → S1-a 이어하기 분기`
- 분기 1 — `[이어하기] → S2 n/16` (저장된 위치)
- 분기 2 — `[새로 시작] → S2 1/16` (기존 진행 폐기 확인 1회)

### F7. 알아보기 진입 (2경로 — 고립 방지)

- 셸 밖 경로 — `S3의 근거 표기 블록 [이 결과의 근거] → T4`
- 셸 안 경로 — `footer [알아보기] → T4`, 복귀는 `T4 하단 [검사 시작] → S1`

## 4. 도달성 점검 — 실제로 확인한 결과

**점검 방법** — ① 모든 화면에 진입 경로가 1개 이상 있는지 ② 모든 버튼의 목적지가 지정됐는지 ③ 출구 없는 화면이 있는지, 세 가지를 화면 단위로 대조

| 화면 | 진입 경로 | 출구 |
| --- | --- | --- |
| S1 | 직접 진입 · T1 탭 · T4 하단 CTA · T2-a·T3-a 빈 상태 CTA · T2 [재검사] | 검사 시작 → S2 / `returnTo` 기록 시 닫기(×) → 기록된 T2·T3·T4 |
| S2 | S1 시작 · S1-a 이어하기 | 다음 → S2 n+1 또는 S3 / 뒤로 → S2 n-1 또는 S1 |
| S3 | S2 16/16 · 공유 URL · T2 항목 탭 · T3 열 탭 | 저장 → T2 / 비교 → T3 / 근거 → T4 / 공유 → S3-d |
| S3-c | S3 결과 저장 | 저장 → T2 / 닫기 → S3 |
| S3-d | S3 공유·카드 | 이미지 저장 · 링크 복사 · 기기 공유 → action / 닫기 → S3 |
| T1 | footer | S1 |
| T2 | footer · S3-c 저장 완료 | 항목 → S3 / [재검사] → S1 / 빈 상태 → S1 |
| T3 | footer · S3 비교 진입점 | 항목 → S3 / 빈 상태 → S1 |
| T4 | footer · S3 근거 블록 | 검사 시작 → S1 |

**점검에서 실제로 발견하고 고친 결함 5건** — 강사 예제의 `추천 콘텐츠 미연결`과 같은 부류

1. **셸 고아화** — `T1 검사` 탭이 footer 없는 S1으로 나가므로, S1에 복귀 수단이 없으면 셸이 다시 도달 불가 상태가 됨 → 자체 점검에서 × 규칙을 추가했으나, 독립 검토가 `S1 → S2 → 뒤로 → S1` 재진입 시 기존 "셸에서 진입한 경우" 조건이 깨짐을 확인하여 **원 화면을 기록하는 `returnTo` 컨텍스트와 T2·T3·T4 복귀 규칙**으로 수정
2. **T4 고립** — S3에 footer가 없어 `알아보기`가 footer로만 도달 가능했음. 공유 링크 진입자는 셸을 못 봄 → **S3 근거 표기 블록에 T4 링크를 필수 요소로 지정**(F7)
3. **T3-a 막다른 화면** — 1마리 상태의 비교 화면에 CTA가 없으면 빈 화면이 실패로 읽힘(§11-4 3) → `한 마리 더 검사` → S1 고정
4. **T2-a 막다른 화면** — 기록 0건 화면에 출구 없음 → `검사 시작` → S1 고정
5. **S3에서 브라우저 뒤로 → S2 16/16 재진입** — 완료한 검사로 되돌아가 답변을 바꿀 수 있는 상태가 됨 → **전체 퀴즈(S1 시작 → S2 1/16…16/16 → S3)는 하나의 replace 가능한 history entry로 점유**하고 문항 단계 이동과 16/16 → S3 전이를 모두 history replace로 처리함. 공유 링크의 `공유 S3 → 내 고양이도 검사하기 → S1 → S2`도 같은 규칙을 상속하며, S3에는 상단 뒤로 버튼을 두지 않음

**남은 미해결** — 자체 점검에서 "없음"으로 잘못 판정했으며, 독립 검토에서 추가 결함이 확인됨. 아래 항목을 수정 대상으로 반영함. F4의 보관 정책과 §10의 확인 항목은 구조가 아니라 **정책 미확정**으로 남음

## 7. 두 번째 탭 라벨 — `내 기록` 채택

- **선택 근거 (1줄)** — 주 페르소나 A는 고양이 1마리이므로 `내 고양이`는 목록이 1건일 때 어색하고 다묘(C, secondary)의 관점을 top-level 라벨로 승격시키는 반면, `내 기록`은 검사일·재검사·이전 결과·localStorage 한계 고지를 자연스럽게 담고 계정으로 오해되지 않음
- 두 라벨을 **2개 탭으로 분리하지 않음** — 같은 데이터의 같은 목록이며, 탭 수를 채우기 위한 분해는 Material의 equal-importance 조건 위반. `내 고양이`는 문구로만 사용 — S3-b의 `내 고양이도 검사하기` CTA (§11-6)

## 8. 모바일 구현 기준 (구조에 영향을 주는 것만)

- 뷰포트 — `viewport-fit=cover` 사용 시 footer 내부 padding과 본문 마지막 padding 양쪽에 `env(safe-area-inset-bottom, 0px)` 반영 ([WebKit — Designing Websites for iPhone X](https://webkit.org/blog/7929/designing-websites-for-iphone-x/), [MDN — env()](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/env))
- 히트 영역 — footer 각 탭 **≥48×48 CSS px**, 아이콘 시각 크기와 히트 영역 분리. S2 선택지는 각 44px 이상 높이
- 높이 단위 — `100vh` 단독 의존 금지, 전체 화면 패널에만 `dvh/svh` 사용
- 시맨틱 — footer는 `<nav>` landmark, 현재 탭에 `aria-current="page"`, S2 진행 표시에 `aria-current="step"`. 페이지 이동 링크에 `aria-selected`를 붙이지 않음
- 현재 위치는 색만으로 표시하지 않음(2개 이상 신호) — 어떤 신호를 쓸지는 **Srit의 Figma 결정 사항**
- **iOS는 미검증 설계 대상** — Android Chrome만 테스트 가능. 발표에서 "iOS 확인 완료"로 쓰지 않음 ([AGENTS.md](../../AGENTS.md))

## 10. 불확실·확인 필요 — 추측을 확정으로 쓰지 않은 지점

1. **S1과 검사 전 안내의 통합** — 03 §11-2는 `시작 → 안내` 2단계로 읽히나 본 문서는 1화면으로 합침(§6 S1). 04-ia §4-2 분류를 따른 결정이며, 강사가 온보딩 화면을 따로 요구하면 화면 1개 추가로 되돌릴 수 있음
2. **재검사 보관 개수** — 개체당 직전 1회분만 보관(F4). 03 §10은 "이전 결과 비교"만 요구하고 개수를 정하지 않음
3. **모르겠음 허용 비율의 수치** — 03 §11-3은 "일정 비율 초과"까지만 규정. 문항 설계 단계에서 결정
4. **S3의 두 컨텍스트(footer 유무)** — 구조상 필요하나 구현 분기 1개가 생김. 단순화를 원하면 "S3는 항상 footer 없음 + T2 재열람도 셸 이탈"로 바꿀 수 있으나, 탭 내부 drill-down 관례에서 더 멀어짐
5. **`비교` 탭의 잔여 위험** — 첫 화면 노출은 피했으나, 셸 안에서는 secondary 기능이 primary와 동등하게 보임. 03 등급 판정과의 긴장은 완전히 해소된 것이 아니라 **첫 화면 밖으로 옮겨진 것**
6. **T3의 3열 스와이프** — 4마리 이상이면 비교 가독성이 떨어짐. 다묘 상한을 정할지는 미결
