### 1-5. 조사에서 나온 판단 포인트

- **`apis.data.go.kr`는 게이트웨이가 Origin을 반사한다** → data.go.kr 계열은 브라우저 직접 호출이 기술적으로 가능해 보임. 그러나 (a) 성공 응답 헤더 미확인, (b) 키가 URL에 노출, (c) 개발계정 1,000/일이 방문자 수에 비례해 소모됨 → **결론: 전부 Actions cron 스냅샷 방식으로 간다.** 시험일정·과목·종목 데이터는 거의 변하지 않아 **주 1회 cron으로 충분**하고, 데모 당일 외부 장애에 면역이라는 부수 효과가 크다.
- **q-net 레거시 호스트(`openapi.q-net.or.kr`)는 키를 검증하지 않는 것으로 보임.** 편하지만 **비공식 동작이므로 의존하면 안 된다.** 정식 키를 발급받아 쓰고, 키 없이도 되는 건 "개발 중 즉시 착수 가능" 이점으로만 활용할 것.
- **NEIS 학사일정에 `중간고사` 이벤트가 실제로 들어있음**을 2개 학교에서 확인 → "내 학교 시험일 자동 불러오기"가 실현 가능. 단 **미등록 학교 존재**(INFO-200) → 수동 입력 폴백 필수.
- **한국어 문제 콘텐츠를 주는 API는 사실상 없다.** 국가자격 공개문제는 PDF 링크뿐, Open Trivia DB는 영어 192문항(컴퓨터). → **퀴즈형 주제는 전부 "직접 문제 작성" 비용을 떠안는다.**

## 2. 후보 주제

### 후보 A — 시험일 역산 학습 플래너 (현 유력안, 강화판)

- **한 줄**: 목표 시험일을 API에서 가져와 남은 기간에 과목·챕터를 자동 배분하고, 밀리면 남은 날짜로 다시 배분해 주는 개인 학습 플래너.
- **등록 → 검색 → 결과**
  - 등록: 자격증 종목 선택(613종목 스냅샷에서 검색) + 학교/학년 선택 + 하루 가능 학습량(분 또는 챕터 수) + 제외 요일
  - 검색: 시험일 조회 — ① 국가자격 시험일정(원서접수/시험/발표) ② NEIS 학사일정의 `중간고사`·`기말고사` ③ 과목·문항수로 학습 단위 자동 생성
  - 결과: 주차별 역산 플랜 + 진도 체크 + **지연분 재배분** + D-day/달성률
- **데이터 출처**
  - `국가자격 시험일정`(data.go.kr 키, Actions 주 1회) → `data/exam-schedule.json`
  - `종목 목록 613건`(키 불필요, Actions 1회) → `data/jm-list.json`
  - `시험교시 과목 정보`(키 불필요, Actions) → 과목명·문항수·수험시간 → **챕터 리스트 초기값 자동 생성**
  - `NEIS 학사일정`(CORS `*`, 브라우저 직접 호출 가능) → 학교 시험일
  - `공휴일`(Nager.Date, 키 불필요) → 학습 가능일 계산에서 제외
  - 사용자 상태 전부 `localStorage`
- **이 학생이 만들 자격**: 직업계고 재학 + 자격증 준비 당사자. 본인이 실제로 겪는 "시험일은 아는데 언제 뭘 해야 할지 모른다"가 문제 정의로 그대로 쓰인다. 기존 포트폴리오(WeaAir)에서 이미 공공 API를 다뤄봤으므로 API 연동 서술이 진화로 읽힌다.
- **가장 어려운 한 가지**: 재배분 알고리즘 자체가 아니라 **프레임워크 없이 캘린더/주차 뷰를 다시 그리는 비용**. 체크 하나에 전체 플랜이 바뀌므로 렌더링·상태 동기화 설계를 처음부터 잡아야 한다.
- **7일 현실성**: **높음.** 콘텐츠 작성 0. API 4종 중 3종이 키 불필요. 최악의 경우 캘린더를 "주차별 리스트"로 낮추면 기능은 그대로 남는다.
- **포트폴리오 위험**: 첫인상이 **투두/캘린더 클론**으로 읽힐 수 있음 → 감점 요소. 방어는 "역산·재배분 알고리즘 + 3개 API 조합 + 지연 시나리오 UX" 를 화면에서 즉시 보이게 만드는 것.

### 후보 B — 기출 회차 채점·약점 분석기

- **한 줄**: 자격증 기출 PDF를 보며 답만 입력하면 과목별 정답률·회차별 추이·취약 과목을 자동으로 뽑아주는 셀프 채점 노트.
- **등록 → 검색 → 결과**
  - 등록: 종목 선택 → 과목·문항수 API로 **답안 그리드가 자동 생성**(정보처리기사 = 과목 5개 × 20문항 등)
  - 검색: 회차 검색 → 공개문제 첨부파일 URL(있는 종목) 또는 사용자가 보유한 회차 직접 추가
  - 결과: 채점 + **문항번호 → 과목 매핑으로 과목별 정답률**, 회차 추이 그래프, 오답 문항 재도전 큐
- **데이터 출처**: `시험교시 과목 정보`(키 불필요 — 문항수·과목명·수험시간이 그리드/타이머의 근거), `종목 목록`, 선택적으로 `공개문제`(PDF 링크). 문제 텍스트는 애초에 앱이 갖지 않는 설계 → PDF-only 한계가 약점이 아니라 전제가 된다.
- **이 학생이 만들 자격**: 기출 돌리기가 실제 학습 방식. "채점을 손으로 하니 과목별 약점을 모른다"는 개인 문제에서 곧바로 출발한다.
- **가장 어려운 한 가지**: **60~100문항 답 입력 UX.** 키보드만으로 빠르게 찍을 수 있어야 하고, 그게 안 되면 앱을 안 쓴다. 여기가 이 앱의 전부다.
- **7일 현실성**: **높음.** 콘텐츠 작성 0, 알고리즘 단순, API 1종만 있어도 성립.
- **포트폴리오 위험**: 낮음. 흔한 클론 카테고리에 속하지 않음. 다만 `공개문제` API의 **종목·회차 커버리지를 키 없이 검증하지 못했다** → PDF 링크가 부실하면 "회차 검색" 단계가 사용자 수동 입력으로 축소된다(치명적이지는 않지만 API 활용도가 떨어진다).

### 후보 C — SQL 셀프 채점 연습장 (sql.js 브라우저 실행)

- **한 줄**: 브라우저 안 SQLite에 문제 스키마를 심고, 작성한 쿼리 결과를 정답 결과셋과 비교해 즉시 채점하는 SQL 연습장.
- **등록 → 검색 → 결과**: 문제셋/문제 등록(직접 추가 가능) → 문제 검색·유형 필터 → 쿼리 실행 결과 비교 채점 + 오답 노트 + 유형별 정답률
- **데이터 출처**: `sql.js` CDN(스크립트 1줄, 빌드 불필요, 완전 오프라인). 문제·스키마·정답은 **직접 작성한 정적 JSON**. Judge0 SQLite(`language_id 82`)를 대안 실행기로 붙일 수 있음(검증 완료).
- **이 학생이 만들 자격**: **가장 높음.** Oracle/SQL·MySQL을 지금 배우는 중이고, 채점 없는 실습이 실제 불편이다.
- **가장 어려운 한 가지**: **문제 콘텐츠 작성.** 그리고 **SQLite ≠ Oracle** — `ROWNUM`, `DECODE`, `(+)` 조인, `NVL` 등 수업에서 쓰는 문법이 안 돌아간다. 학교 진도와 어긋나는 도구가 된다.
- **7일 현실성**: **중간.** 구현은 3~4일이면 되지만 문제 20~30개 작성이 별도 1~2일. 2인이면 1명이 콘텐츠 전담 가능.
- **포트폴리오 위험**: 낮음(오히려 강함). 단 **Oracle 불일치를 설명 못 하면 "SQL 잘 모른다"는 역효과**가 난다. 정직하게 "SQLite 표준 문법 범위" 로 좁히면 방어된다.

### 후보 D — Java 코드 제출·자동 채점 연습장 (Judge0 CE)

- **한 줄**: 문제를 고르고 Java 코드를 작성하면 실제로 컴파일·실행해 기대 출력과 비교하고, 컴파일 에러 유형까지 누적 통계로 보여주는 연습장.
- **등록 → 검색 → 결과**: 문제 등록/선택 → 문제 검색 → 실행 결과 비교 + 에러 유형 통계 + 재도전 이력
- **데이터 출처**: Judge0 CE 공용 인스턴스(키 없음, CORS `*`, Java JDK 17 실행 확인). 문제·기대출력은 직접 작성. 에디터는 CodeMirror CDN.
- **이 학생이 만들 자격**: 높음(Java 수강 중).
- **가장 어려운 한 가지**: **데모 당일 외부 의존.** Judge0 CE는 공식적으로 production 비권장이고, 다운되면 앱의 핵심 기능이 0이 된다. 캐시 폴백으로 가릴 수 없는 종류의 기능이다.
- **7일 현실성**: **중하.** 콘텐츠 작성 + 에디터 통합 + 가용성 리스크가 겹친다.
- **포트폴리오 위험**: 개념은 매력적이나 **발표장에서 안 돌아갈 확률**이 다른 후보보다 명확히 높다.

### 후보 E — 간격 반복(SM-2) 오답 카드

- **한 줄**: 오답을 카드로 등록하면 SM-2 알고리즘이 복습 날짜를 잡아주고, 태그별 취약 영역을 보여주는 암기장.
- **등록 → 검색 → 결과**: 카드·태그 등록(붙여넣기 일괄 입력) → 태그·정답률 검색 → 오늘의 복습 큐 + 스트릭 + 취약 태그
- **데이터 출처**: **사용자 입력 + `localStorage`가 전부.** 선택적으로 Wikipedia 요약으로 카드 뒷면 보강(CORS `*`).
- **이 학생이 만들 자격**: 보통. 개인 문제로는 성립하지만 전공 역량과의 연결이 약하다.
- **가장 어려운 한 가지**: 대량 카드 입력 UX(이것도 결국 입력 문제).
- **7일 현실성**: **높음**(콘텐츠를 사용자가 만들어 준다).
- **포트폴리오 위험**: **Anki 클론**으로 읽힘. 더 큰 문제는 **API 활용이 사실상 0** → "공개 API 연동"을 기대하는 과제 성격과 충돌.

## 3. 순위와 결론

| 순위 | 후보 | 7일 현실성 | 데이터 리스크 | 차별성 | 학생 신뢰도 | 종합 판단 |
|---|---|---|---|---|---|---|
| **1** | **A. 시험일 역산 학습 플래너** | 높음 | 낮음(4개 API 중 3개 무키, 데이터 준정적) | 중(첫인상 리스크 있음) | 높음 | **유력안 유지.** 콘텐츠 작성 0 + 등록→검색→결과 매핑이 가장 자연스럽고, 조사 결과로 오히려 강해졌다 |
| **2** | **B. 기출 채점·약점 분석기** | 높음 | 중(공개문제 커버리지 미확인, 단 API 1종만으로도 성립) | **높음** | 높음 | **가장 강한 대안.** 차별성만 보면 A보다 위. 순위가 낮은 이유는 앱의 성패가 "답 입력 UX" 단 하나에 걸려 있어 실패 시 만회할 여지가 없다는 점 |

### 결론

- **유력안 A는 살아남는다.** 유지 근거 3가지:
  1. **콘텐츠 작성 부담이 0인 유일한 상위 후보** — 7일 중 실제 개발일이 4~5일뿐인 상황에서 이게 결정적이다(C·D는 문제를 직접 써야 한다).
  2. **조사로 앵커가 3개 더 붙었다** — `종목 목록 613건`(무키)로 등록 단계의 검색이 진짜 검색이 되고, `과목·문항수`(무키)로 챕터 리스트를 자동 채워 최초 진입 마찰이 사라지고, `NEIS 학사일정`(CORS `*`)의 `중간고사` 이벤트로 "내 학교 시험"까지 커버된다. 원래 안의 최대 약점("사용자가 챕터를 다 타이핑해야 한다")이 API로 해결됐다.
  3. **데이터가 준정적이라 Actions cron 주 1회면 충분** → 발표 당일 외부 장애 리스크가 실질적으로 없다.
- **단, A는 조건부 승리다.** 캘린더·체크리스트 화면만 보여주면 투두 클론으로 읽혀 감점된다. 발표에서 **"3일 밀린 상태 → 남은 날짜로 재배분되는 순간"** 을 데모의 중심에 두고, 역산·재배분 규칙을 화면 위에 명시해야 방어된다.
- **B를 죽이지 말 것.** A에 "회차 채점" 을 얹는 건 7일 안에서는 범위 초과지만, 9월 이후 확장 항목으로 기획서에 남겨두면 A의 서사가 "학습 계획 → 실행 → 검증" 으로 완결된다. 만약 A의 재배분 알고리즘이 3일차에 막히면 **B로 갈아타는 것이 유일하게 합리적인 후퇴로**다(과목·문항수 API를 이미 붙여둔 상태라 자산이 남는다).

### 최대 실현 리스크 (단일)

- **API가 아니라 렌더링이다.** A의 역산 계산 자체는 반나절이면 끝나지만, **프레임워크 없이 "체크 1회 → 전체 플랜 재계산 → 캘린더 전체 재렌더" 를 상태 꼬임 없이 만드는 비용**이 예상의 2배가 되기 쉽다. 이게 터지면 진도 체크와 재배분이 동시에 무너져 앱의 핵심 기능이 사라진다.
- 완화: ① 1일차에 "단일 상태 객체 → `render()` 전체 재호출" 구조를 못 박고 부분 갱신 최적화는 금지 ② 캘린더 그리드는 3일차까지 안 되면 **주차별 리스트로 강등**(기능 손실 없음) ③ data.go.kr 개발계정 키는 **08-05 오전에 즉시 신청**(자동승인이지만 반영 지연이 있음). 키 발급 전에도 무키 API(종목·과목·NEIS·공휴일)로 개발을 시작할 수 있다는 점이 이 조사의 실용적 이득이다.
