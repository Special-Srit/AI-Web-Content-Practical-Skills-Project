## 제품 프레이밍

> 오늘의 기분을 고르면 내 음악 중에서 어울리는 곡을 꺼내 주고, 다 듣고 나서
> 그날의 기분을 한 줄로 남겨 두는 플레이어.

`../Eng/03-idea-scan-positioning.md`가 요구한 완성된 루프를 그대로 유지:

| 단계 | 이 앱에서의 구현 |
| --- | --- |
| 입력 | 오늘의 기분 선택 |
| 결정 | 추천된 곡 중에서 고르기 · 재생 |
| 결과 | 들은 곡과 그때의 기분이 남음 |
| 저장된 성찰 | **오늘의 기분 일기** — 날짜별로 누적 |

**“Music Player”가 아닌 이유.** `03`의 레드 플래그는 *My Todo*나 *Weather App*으로
부를 수 있는 제목이다. “기분 일기가 붙은 플레이어”는 A–B loop와 같은 방식으로 이
테스트를 통과한다. 결정과 저장된 성찰이 있기 때문이다. 순수 플레이어에는 둘 다 없다.

**Spotify가 아닌 이유.** 카탈로그가 없으므로 카탈로그 경쟁을 하지 않는다. 차별점은
라이브러리가 *사용자 것*이고 앱이 각 트랙의 감정을 기억한다는 점이다. 스트리밍
서비스는 의도적으로 하지 않는 일이다.

## 콘텐츠 문제 — 다른 일보다 먼저 해결

**카탈로그 없음. 라이선스 없음. 저장소는 공개.**

상업용 트랙을 포함하면 저작권 침해가 되고 git 기록에 영구적으로 남는다.

스트리밍 연동은 **법이 아니라 범위로 제외**한다(2026-08-05 sol 검토 수정).
Spotify의 Web Playback SDK와 YouTube의 IFrame API는 자체 조건 아래 브라우저 재생을
허용한다. 어느 것도 이 사용을 허용하지 않는다는 이전 주장은 근거가 부족했다. 제외
이유는 인증, 네트워크 의존성, 서비스별 UX와 정책 의무를 추가하고 로컬 라이브러리라는
핵심을 약화하기 때문이지, 금지되어서가 아니다.

사용하는 두 가지 법적 출처:

| 출처 | 역할 | 규칙 |
| --- | --- | --- |
| **번들 데모 세트** | 노트북의 파일 picker에 의존하지 않고 08-14에 동작 | **검증된 CC0 또는 CC BY만**(아래 규칙 참조). 커밋 전에 모든 파일을 `public/audio/CREDITS.md`에 기록하고 배포 앱 안에도 크레딧 표시 |
| **사용자 자신의 파일** | 실제 라이브러리 | `07`과 같은 File picker. 어디에도 업로드하지 않음 |

번들 세트의 실용적 제한:

- **트랙 4~5곡, 각 30~60초** 목표(8~12곡에서 축소, sol 검토). 전체 폴더는 **약
  20MB보다 훨씬 작게** 유지 — 이 저장소는 08-05에 이미 14MB → 1.6MB 기록 정리를
  했고, 오디오는 이미지보다 git을 훨씬 크게 만든다.
- MP3 또는 AAC만(`07` 포맷 규칙 — MP3/AAC만 보편적으로 안전한 디코드 대상).
- **검증된 CC0 또는 CC BY 녹음만 허용.** 넓은 의미의 “CC 또는 퍼블릭 도메인”이
  아님(sol 검토) — NC는 학생 신분이 아니라 사용 방식에 따라 달라지고, SA는 재배포된
  2차 저작물에 적용되며, ND는 잘라낸 excerpt의 배포를 금지할 수 있다. 퍼블릭 도메인
  *작곡물*이라고 해서 현대 녹음까지 퍼블릭 도메인이 되는 것은 아니다.
- **Pixabay는 후보 목록에서 제거.** CC가 아닌 독점 Content License를 사용하며
  standalone 재배포를 금지한다 — 공개 음악 플레이어 저장소에 raw audio를 커밋하는
  경우가 바로 여기에 해당한다.
- 남은 후보. 사이트가 아니라 트랙별로 각각 **검증**한다:
  - **Free Music Archive** — 라이선스가 트랙별이고 NC/ND/SA를 포함하며, 일부 폐기된 트랙은 듣기만 가능
  - **ccMixter** — remix에 여러 기여자와 sample source가 포함될 수 있으므로 전체 연결 고리가 재배포를 허용해야 함
  - **Jamendo Music**만 사용(개별적으로 CC0/CC BY 검증). 별도 유료 마켓플레이스인 **Jamendo Licensing**은 제외하고, API에서 가져온 파일도 제외
  - **incompetech** — 무료 옵션은 CC BY이며 **눈에 보이는** 크레딧이 필요. 무표기 경로는 유료
- 트랙마다 기록: 제목 · 제작자 · 출처 URL · 정확한 라이선스와 버전 · 받은 날짜 ·
  **자르거나 변환했다는 사실**
- **크레딧은 저장소뿐 아니라 배포 앱에도 표시** — CC BY는 사용자가 쉽게 찾을 수 있는
  곳에 크레딧을 요구한다
- 라이선스를 확실히 확인할 수 없으면 트랙을 제외한다.

**태그 파싱 없이는 embedded artwork를 사용할 수 없다.** `File`은 `name`과
`lastModified`를 노출하고 `Blob`에서 `size`, `type`, bytes를 상속하지만 음악 태그를
파싱하지 않는다. artwork가 bytes 안에 들어 있을 수는 있지만, 읽으려면 MP3의 ID3v2
`APIC` frame과 MP4/M4A의 `meta`/`ilst`/`covr` atom을 인코딩 및 손상 데이터와 함께
처리해야 한다. **Tag parsing은 범위 밖**이므로 실제로 picked 파일에는 cover art가 없다.

따라서 cover는 (a) 같은 라이선스 확인을 거쳐 번들 데모 세트와 함께 제공하거나,
(b) mood tag에서 유도한 생성 placeholder로 처리한다. **사용자가 고른 파일에는
(b)가 기본값**이며, 누락 이미지가 아니라 실제 상태로 디자인한다.

## Data contract — 두 사람이 코드를 쓰기 전에 동결

`07`의 Track/LoopMark/Attempt 모델을 대체한다.

```js
// Track
{ id, title, artist, fileName, size, lastModified, durationSec,
  addedAt, lastPlayedAt,   // 최근 재생 정렬용
  source: 'bundled' | 'picked',
  assetUrl,        // 번들 곡의 재생 경로. picked면 null
  artworkUrl,      // 번들 곡만. picked면 null → MoodArtwork로 대체
  favorite,        // ♡ — 좋아요한 음악
  moods: [MoodId] }

// Playlist — 수동 생성
{ id, name, trackIds: [], createdAt, updatedAt }

// DiaryEntry
{ id, localDate, createdAt, mood: MoodId, text, trackIds: [] }

// PlayerState — 메모리만
{ trackId, status, positionSec, error,
  queue: [trackId], queueIndex,
  repeat: 'off' | 'one' | 'all',
  shuffle: false }
```

- `status` — `'idle' | 'loading' | 'playing' | 'paused' | 'error'`. 이 5개가 전부다
- `queue`는 재생을 시작한 맥락의 곡 목록이다 — 기분 필터 결과, 플레이리스트,
  또는 라이브러리 섹션. 어디서 눌렀는지가 큐를 정한다
- `shuffle`은 `queue`의 재생 순서만 바꾼다. 원본 배열은 건드리지 않는다
- `error` — `{ code, message }` 또는 `null`. 코드는 `07`의 에러 분류를 따르되
  **`BAD_LOOP_RANGE`는 제외**한다 (A–B 루프가 사라졌으므로)
- **`assetUrl`이 없으면 번들 곡을 재생할 방법이 없다** — sol 검토에서 잡힌 구멍
- Keys — `musicdiary:v1:tracks | playlists | diary | settings | schemaVersion`
- **`Playlist.trackIds`의 순서가 곧 재생 순서다.** 순서 변경은 이 배열을 바꾸는 것
- 트랙을 지우면 모든 플레이리스트의 `trackIds`에서도 빼야 한다. 고아 ID를 남기지 말 것
- `settings` — `{ autoPlay, sleepTimerMin, theme, notifications }`. 이게 전부다.
  음질·EQ·크로스페이드는 없다 (§걷어낸 것)
- **`MoodId`는 안정적인 영문 식별자**이고 화면 라벨과 분리한다. 라벨을 바꿔도
  저장된 데이터가 깨지지 않게 하기 위한 것

  | MoodId | 라벨 |
  | --- | --- |
  | `calm` | 차분함 |
  | `flutter` | 설렘 |
  | `comfort` | 위로 |
  | `focus` | 집중 |
  | `longing` | 그리움 |

- **같은 어휘를 음악 필터와 일기에 함께 쓴다.** 목록 하나, 용도 둘
- `localDate`는 `YYYY-MM-DD` 로컬 기준 문자열, `createdAt`은 ISO 타임스탬프.
  **하루 한 건**이며 같은 날 다시 쓰면 덮어쓴다
- **트랙을 지우면 일기의 `trackIds`가 고아가 된다.** 일기는 지우지 않고, 사라진
  트랙은 “삭제된 곡”으로 표시한다. 기록이 조용히 바뀌면 안 된다
- **`fileName + size + lastModified`로 picked 파일 재연결** — 단 이것은
  **식별자가 아니라 휴리스틱**이다(sol 검토). 서로 다른 파일이 같은 튜플을 가질 수
  있고, 복사본은 튜플을 보존하며, 이름이나 타임스탬프가 바뀌면 못 찾는다.
  유일하게 일치할 때만 자동 연결하고, 충돌하면 사용자가 고르게 하며, 수동 재연결을
  항상 허용한다. 해싱은 휴리스틱이 부족하다는 게 확인되기 전에는 넣지 않는다
- 재선택은 **이 MVP의 저장 결정이지 API 한계가 아니다.** `File`은 직렬화 가능하고
  IndexedDB에 넣을 수도 있다. 우리는 메타데이터만 저장하고 다시 고르게 하는 쪽을 택했다
- 로드 시 **형식 검증**을 하고, 깨진 데이터는 초기화 경로로 보낸다.
  `schemaVersion`은 있는 것만으로는 아무 일도 하지 않는다
- **전체 삭제는 `musicdiary:*` 키만 지운다.** `localStorage.clear()` 금지 —
  같은 오리진의 다른 페이지 데이터까지 날아간다
- `title`은 picked 파일의 파일명에서 유도하고 `artist`는 선택 입력이다. ID3 파싱 없음

### 저장·프라이버시에 관한 정직한 표현

- “파일이 업로드되지 않는다”는 **API 보장이 아니라 구현 약속**이다. 분석 스크립트나
  서드파티 런타임 스크립트를 넣지 않고, 파일 선택 후 네트워크 탭으로 확인한다
- GitHub Pages 프로젝트 사이트는 **소유자 단위로 오리진을 공유**한다. 같은 오리진의
  다른 페이지가 같은 `localStorage`에 접근할 수 있다. 키 네임스페이스는 충돌을 막을
  뿐 접근을 막지 못한다. 앱 안에서 이 점을 숨기지 말고 그대로 알린다
