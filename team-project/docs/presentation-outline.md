장르 분류 셋 다 **같은 이유**(데이터·구조 없음)로 뺀 항목으로 묶는다 — 취향으로
자른 예시가 아니다. 아래처럼 하나의 사실로만 말한다: "이퀄라이저·크로스페이드·태그
자동분류는 취향이 아니라 각각 Web Audio 그래프·두 번째 오디오 요소·ID3 파서가
필요해서 현재 구조에서 뺀 것입니다."

▶ 스크립트: "프롬프트 원문은 `docs/prompts/`에 그대로 남아 있습니다. 저희가 강조
드리고 싶은 건, AI가 낸 결과를 검토 단계에서 실제로 걸러냈다는 점입니다."

**[디자인]** 실제 프롬프트 원문 발췌 1~2개는 `[디자인]` — 이 슬라이드 또는 부록에
스크린샷/인용으로 삽입(다음 패스에서 문구 확정).

# 07 · 실제 차이와 정직한 한계 (8분판 1:10, 08과 합쳐 5분판 0:45)

**[타입]** `slide-content`

- 챕터 라벨: `04 · 한계`
- 제목: **정직하게 말씀드리는 제약**
- 부제: `계정·백엔드가 없다는 것은 제약이자 약속`

본문 (2열):

| 목표 | 감수하는 것 — 취향이 아니라 이번 MVP의 결정 |
| --- | --- |
| 목표: 파일을 서버에 전송하지 않는 로컬 처리 (구현 후 네트워크 탭으로 검증 예정) | 새로고침 후 파일을 다시 선택해야 함 — 이번 MVP가 파일 본문 대신 메타데이터만 저장하기로 한 결정(IndexedDB로 파일 자체를 저장하는 방식도 가능하지만 채택하지 않음) |
| 계정 없이 바로 사용 | 다른 기기로 옮기면 기록이 이어지지 않음 |
| 라이브러리는 사용자 자신의 파일 | 장르·앨범 자동 분류 없음 — ID3/MP4 태그 파서를 이번 범위에 넣지 않기로 한 결정(불가능이 아니라 범위 제외) |

**[정정]** 이전 버전은 "비공개·오프라인 — 파일이 어디로도 업로드되지 않음"을
이미 검증된 사실처럼 썼다. `08-concept-music-diary-KR.md` §저장·프라이버시는 이걸
**구현 약속**이라고 명확히 하며(API 보장이 아님), 코드가 생긴 뒤 네트워크 탭으로
직접 확인해야 한다고 못박는다 — 지금은 "목표"로만 말한다. 같은 이유로 파일
재선택·태그 자동분류 없음도 "브라우저가 못 해서"가 아니라 **이번 MVP가 그렇게
설계하기로 한 결정**이라고 정확히 말한다.

▶ 스크립트: "이건 저희가 숨기는 대신 먼저 말씀드리는 한계입니다. 계정이 없다는
선택이 이 한계를 만들지만, 동시에 '비공개·오프라인'이라는 목표이기도 합니다."

**[디자인]** 파일 재연결이 완전한 식별자가 아니라 휴리스틱이라는 점(`08-concept`
§Data contract)은 시간이 되면 이 슬라이드, 안 되면 Q&A 답변으로.
